# CLAUDE.md - Learning Scout APP

## 产品常识（必须知道）

这是一个 AI 学习助手 APP，面向真实用户。不是练手项目，不是 demo，不是"功能有了就行"。

### 用户旅程（每个环节必须完整）

```
首次打开 → 登录/注册 → 问卷（18题树状） → 主页（4个Tab）
再次打开 → 登录（token有效）→ 主页
退出登录 → 登录/注册页面（不是主页！）
```

**这条规则没有例外。** 只要用户点了退出登录，下一步必须看到登录页。

### UI 底线

- 设计稿里有的功能 → 必须实现
- 设计稿里没写的必要功能（登录、注册、退出） → 必须补充，补充前先说
- 所有按钮都能点，点了一定有响应
- 永远不要让用户看到空白的按钮、404、无法交互的界面

### 中文优先

所有面向用户的文字必须是中文。按钮、提示、错误信息、标题，全部中文。

## 行动前必须思考（三步法）

### 1. 意图挖掘

用户说"做一个聊天界面"，他们真正想要的是：
- 能发消息、能收到 AI 回复
- 对话能保存、能切换
- 不是"有个输入框就完事了"

### 2. 上帝视角

如果只按字面意思做：
- "登录页面"可能只有输入框，没有注册、没有错误处理、没有加载状态
- "聊天"可能只能发不能收，或者没有对话历史列表

### 3. 更优解

先问：
- 这个功能有没有后端 API？没有的话 mock 还是先说？
- 这个功能有没有参考页面？（查 APP UI.txt）
- 边界情况怎么处理？（网络失败、token 过期、数据加载中）

---

## 实现任何功能前的 Checklist

- [ ] 理解用户真正想要什么（不只是字面意思）
- [ ] 确认涉及的 API 有没有
- [ ] 确认 UI 设计稿里有没有
- [ ] 如果设计稿没有必要功能，先告诉用户
- [ ] 列出要改的文件
- [ ] 有疑虑先说，不要猜

---

## 技术约束

- **必须调用真实后端 API**，不要 mock
- **答案存储用 option.id**，不要用 option.text
- **所有 API 调用都要处理 401**（token 过期 → 跳转登录）
- **提交表单要有 loading 状态和防抖**
